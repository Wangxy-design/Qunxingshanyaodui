## 一、入门准备：学习方法、练手项目与团队分工

**功能描述：** 时间：正式动手做小车之前的一段时间 本部分记录：电控入门思路、练手项目、团队分工的调整过程

**开发历程（正式动手之前）：**

**入门：开始学做电控：**

**一开始先从 C 语言学起**

刚开始接触电控的时候，我的第一反应是先打好基础——从 C 语言学起。想着把语法、指针、结构体这些都学明白了再动手。

但真正学起来才发现，按这个学习方法进度太慢。C 语言在没有实际运用的时候，学习困难，理解不够深入。更重要的是，中期考核有时间节点。

**换个思路：边做边学**

所以后来调整了方法：直接从实操开始，边做边学习补充原理。

具体方法：先把需要的东西搭建起来，让程序跑出一个结果，遇到不懂的概念原理就立马查、当场理解。在这个学习方法里我也找到了此方法的好处。具体如下：

①知识点有落脚点。比如学"时钟"，是因为舵机角度要用；学"链接"，是因为编译报错了要去解决。由问题驱动着去学，既能补充知识点原理，也能理解更透彻。

②进度清晰。每搞通一个小功能，都能实实在在看到现象，有正反馈，不容易感觉迷茫。

③代码这块可以借助 AI ，所以我主要学习理解"这个代码在干什么""为什么这么接"上，而不是从零手搓每一行。

PS:这也是我做小夜灯练手项目时验证过的：先让东西动起来，再搞懂它为什么动，比直接啃理论要快。

**为什么选择这个方式**

电控是工程项目，而非考试。工程能力靠的是"把东西做出来"的经验，而不是背下来多少语法。语法可以查，但"遇到问题怎么定位、怎么一步步排除"这种解决实际问题的能力，只能在动手过程中练出来。

**练手项目：光控小夜灯：**

在正式开始造小车之前，我先用 Arduino 做了一个很小的项目练手——光控小夜灯。

从这个小项目入门的原因是：项目小，但完整。它包含了一个完整电控项目的几乎所有环节：传感器输入 → 程序判断 → 输出控制。

**学到什么：**

① 一个完整的"输入→处理→输出"流程是怎么跑通的

光敏电阻检测环境亮度 →输入

程序里比较这个值和阈值 → 处理

后面的舵机控制等，本质上类似即传感器/指令输入 → 程序处理 → 执行器动作。

②调试要有耐心和逻辑

首先是逻辑性：先看是硬件问题还是软件/系统问题。如果是硬件设备问题，将要从插线→配置→硬件本体等不同层次来分析；如果是软件问题，将要从环境→代码等来进行分析。将问题拆解来看。

再就是需要耐心：问题的不同层次的排查需要耐心地进行下去。

**项目意义：**

①一个跑得通的完整项目经验②一套"遇到问题怎么排查"的初步方法。

## 二、开发环境搭建与 STM32 点灯

**功能描述：** 搭建 Keil + CubeMX + ST-Link 的完整开发链路，完成第一个 GPIO 程序（ LED 闪烁），从而验证"配置 → 编译 → 烧录 → 运行"整条链路可用。

**开发历程（10.9-10.10）：**

点灯时CubeMX 关键配置及原因：

1. SYS → Debug = Serial Wire：不勾选的话，PA13/PA14 会被当成普通 IO，ST-Link 直接无法连接。
2. RCC → HSE =Crystal/Ceramic Resonator ：让芯片使用板载 8MHz 外部晶振作为时钟源，再经 PLL×9 倍频得到 72MHz 主频，保证PWM 时序精确。
3. Clock Tree 中 HCLK = 72：F103 的最高主频，定时器精度依赖此时钟。
4. PC13 → GPIO_Output：板载 LED 所在引脚。
5. Toolchain 选 MDK-ARM

**核心代码：**

```c
/* USER CODE BEGIN WHILE */
while (1)
{
    HAL_GPIO_TogglePin(GPIOC, GPIO_PIN_13);
    HAL_Delay(500);
    /* USER CODE END WHILE */
}
```

**遇到问题及解决方案：**

| 问题 | 现象 | 原因分析 | 解决方案 |
| --- | --- | --- | --- |
| ARM-Compiler V5 not available | 编译直接报错 | Keil MDK 5.37+ 不再内置 V5 编译器 | 每个新工程都要在 Target 里改为 Compiler V6（容易忘） |
| 面包板不通 | LED 不亮 | 电路安排有问题 | 更改电路后，在面包板上重新布局后led点亮 |

思考总结：环境搭建阶段的所有报错，本质都是"链路某一环断了"。

养成习惯：报错先定位是哪一环（配置/编译/烧录/运行），不盲目查询。

**Undefined symbol 链接错误排查（在此花费较长时间）**

**现象**

当时舵机代码烧录时报错：

```text
Undefined symbol MX_TIM3_Init      (referred from main.o)
Undefined symbol htim3             (referred from main.o)
Undefined symbol HAL_TIM_PWM_Start (referred from main.o)
"LED\LED.axf" - 3 Error(s)
Target not created.
```

**排查过程与原因**

第一步：定阶段。 编译分两阶段——编译（逐个 .c 翻译成机器码）和链接（把所有目标文件拼成最终程序）。L6218E / Undefined symbol 是链接器报的错，说明问题不在代码写法，而在"某个实现文件没参与编译"。

第二步：定位缺失的符号。检查 Keil 工程树 ，发现 Application/User 组里没有 tim.c。

第三步：修改。 方案是回 CubeMX 重新 GENERATE CODE——让它自动把 tim.c 写入 Keil 工程文件。重新打开工程后 tim.c 出现，编译通过，进而烧录成功。

**方法总结：**

| 错误关键字 | 阶段 | 含义 | 解法 |
| --- | --- | --- | --- |
| error: #20 identifier undefined | 编译 | 代码拼写/头文件问题 | 改代码 |
| L6218E: Undefined symbol | 链接 | 缺 .c 文件 | 把对应 .c 加入工程（或 CubeMX 重新生成） |
| Target not created | 结果 | 前面有错没生成 | 先解决上面的错 |

## 三、舵机 PWM 控制（机械臂执行基础）

**功能描述：** 通过 TIM3 输出 50Hz PWM 波形，控制舵机转到指定角度（500~2500us 脉宽 → 0°~180°），为机械臂三个关节的驱动打基础。

**元件选取(舵机与马达）：**

机械臂需要的是"转到某个角度并保持"，对比两种执行器：

|  | 普通直流马达 | 舵机 |
| --- | --- | --- |
| 引线数 | 2 根（正负极） | 3 根（GND/VCC/信号） |
| 控制方式 | 通电即转，需驱动板+调速 | PWM 脉宽直接对应角度 |
| 能否定角度 | 开环转速控制，无位置反馈 | 转到目标角度锁死 |

**舵机型号选型（针对机械臂各关节）：**

| 型号 | 扭矩 | 电流 | 分工 | 选型理由 |
| --- | --- | --- | --- | --- |
| SG90 | ~1.8 Kg/cm | ~100mA | ❌ 不用于成品，仅作学习/调试教具 | 扭矩太小，抬不动臂，但便宜、适合验证代码 |
| JMP-BE-9100 | 3.0 Kg/cm | ~300mA | ✅ 夹爪开合 | 夹方块负载轻，小舵机够用且轻量化 |
| MG995 ×2 | ~10 Kg/cm | 堵转 1.2~1.8A | ✅ 底座、肘部大关节 | 机械臂自重大，必须大扭矩金属齿舵机 |

**开发历程（10.9-10.10 单路扫角，10.11-10.12 三路全通）：**

**PWM 原理与参数推导：**

舵机不看占空比，看脉宽。

```text
周期 20ms（50Hz）
500us → 0°
1500us → 90°（中位）
2500us → 180°
```

由目标频率反推定时器参数（体现计算过程）：

定时器时钟 72MHz，目标计数周期 20ms

PSC = 71 → 计数频率 = 72MHz / (71+1) = 1MHz，即 1 个计数 = 1us

ARR = 19999 → 计数周期 = (19999+1) × 1us = 20ms = 50Hz

CCR=（脉宽微秒数)=1500→1500 即 1.5ms 脉宽

**核心代码：**

```c
/* USER CODE BEGIN 2 */
HAL_TIM_PWM_Start(&htim3, TIM_CHANNEL_1);   // 不启动输出，PA6 永远没有波形
/* USER CODE END 2 */

/* USER CODE BEGIN WHILE */
while (1)
{
    for (int us = 500; us <= 2500; us += 10) {          // 500us→2500us 缓慢扫过去
        __HAL_TIM_SET_COMPARE(&htim3, TIM_CHANNEL_1, us);
        HAL_Delay(20);
    }
    for (int us = 2500; us >= 500; us -= 10) {          // 再扫回来
        __HAL_TIM_SET_COMPARE(&htim3, TIM_CHANNEL_1, us);
        HAL_Delay(20);
    }
    /* USER CODE END WHILE */
}
```

**三路 PWM 全通，三关节同控**

TIM3 三个通道（CH1/PA6 肩关节、CH2/PA7 肘关节、CH3/PB0 夹爪）全部输出 PWM，三路舵机各自独立受控，动作序列验证通过。

**关键参数**

| 参数 | 值 | 含义 |
| --- | --- | --- |
| PSC | 71 | 预分频，72MHz/(71+1) = 1MHz 计数 |
| ARR | 19999 | 自动重装载，(19999+1)/1MHz = 20ms 周期（50Hz） |

固定值，由舵机固定50hz反推出来。

**工具函数：Servo_SetUs**

```c
/* 直接发脉宽（微秒），跳过角度换算 */
void Servo_SetUs(uint32_t ch, uint16_t us)
{
    if (us < 500)  us = 500;
    if (us > 2500) us = 2500;
    __HAL_TIM_SET_COMPARE(&htim3, ch, us);
}
```

逐段解析：

- uint32_t ch —— 通道号，填 TIM_CHANNEL_1/2/3 决定发给哪个舵机；
- uint16_t us —— 脉宽值（500~2500）。必须用 16 位，8 位（uint8_t）上限仅 255，1500 会被截断成 220，导致逻辑全错；
- 两行 if —— 输入限幅保护
- __HAL_TIM_SET_COMPARE —— 设置定时器比较值。

舵机只看高电平的宽度决定转到哪——0.5ms 转一边、1.5ms 停中间、2.5ms 转另一边。

```text
高 ─┐  ┌────────┐  ┌────────┐
    │  │        │  │        │
低  └──┘        └──┘        └──
    ←1.5ms→
    ←──────── 20ms ────────→
```

| 配置项 | 作用 |
| --- | --- |
| PSC / ARR | 决定”每 20ms 打一拍”（节奏）（定值） |
| __HAL_TIM_SET_COMPARE | 决定每拍里高电平多宽（位置） |

换算参考：角度 =（脉宽 − 500）÷ 2000 × 180。

注：这是舵机转轴的理论角度，与机械臂实际姿态角有偏差（初始位、负载、结构限位等都会影响），因此代码中统一用脉宽数字。

## 四、中位测试与"舵机不动"的系统排查

**功能描述：** 测试舵机能否停在指定角度并保持不动。

**开发历程（10.9-10.10，待解问题延续到 10.11）：**

**为什么中位是 1500us？**

①1500us 是行程的几何中心：(500+2500)/2 = 1500 → 左右各 90° 行程对称。

②在中位装配机械臂，左右调节余量最大

**中位代码**

```c
/* USER CODE BEGIN 2 */
HAL_TIM_PWM_Start(&htim3, TIM_CHANNEL_1);
__HAL_TIM_SET_COMPARE(&htim3, TIM_CHANNEL_1, 1500);
/* USER CODE END 2 */

/* USER CODE BEGIN WHILE */
while (1)
{
    HAL_Delay(1000);    // 所有工作已在初始化完成，循环只维持程序运行
    /* USER CODE END WHILE */
}
```

**遇到问题：** 测试中遇到舵机"时动时不动"

问题一：软硬件查不出毛病，但中位测试仍不运行（尚未解决）：测试时出现舵机一直不动的情况，把所有链接过程都查了一遍：①代码借助ai核对过②编译 0 Error，且烧录显示 Programming Done③接线反复重插，棕GND、红5V、橙PA6 都确认过后续补充

注：但问题一即中位测试仍未解决，耗费时间较长，先将其跳过，进行后续独立供电，准备10.11再次进行中位测试。

问题二：排查时发现一个规律：板子上的蓝灯亮的时候舵机就正常，蓝灯灭了舵机就不动。蓝灯灭说明芯片在反复重启或者供电不稳。推测是供电的问题——现在板子和舵机都靠 ST-Link 供电，它给不了多少电流，而舵机一启动就要几百毫安，很可能把电压拉低，芯片一复位就不输出 PWM 了，舵机自然就停；电压恢复后芯片又重新跑，就这样反复。

预计解决方案：给舵机单独供电，用两节 18650 电池（串联为 7.4V）接 MP1584 降压模块，降到 5V 后专门给舵机供电；板子继续用 ST-Link 供电。

后续需做（10.11）①借万用表把 MP1584 输出调准到 5V②把舵机电源从板子上换到独立电源③重新跑中位测试

（如果蓝灯能稳定常亮、舵机能正常停在指定角度，就说明问题确实是供电不足。如果独立供电后问题还在，再查接线和信号线等。）

## 五、舵机独立供电方案设计与实施

**功能描述：** 用 2 节 18650（串联 7.4V）+ MP1584 降压模块构建独立 5V 电源轨道，专门为舵机供电，使 STM32 与大电流执行器电源解耦。

**开发历程（10.9-10.10 方案设计与预计实施，10.11-10.12 实施）：**

**方案设计与预计实施（10.9-10.10）**

**为什么必须独立供电？**

①未来机械臂上有 2 个 MG995，电流各 1.2~1.8A，板载 5V（USB/ST-Link）不能承受。

②即采用各自供自己的电的方法。

**预计实施：**

①实现独立供电：借万用表，将 MP1584 输出精确调至 5.0V 后再接舵机；

②三路 PWM 分别驱动底座/肘部/夹爪；

③编写三路代码；

④机械臂装配及试运行；

⑤再次执行中位测试；

⑥将机械臂与手柄相连接；

⑦小车初组装；

⑧调试更改；

……

**实施（10.11-10.12：从独立供电到三关节安全范围测定）**

**为什么要独立供电**

机械臂上有 2 个 MG995和1个9100舵机，舵机工作300~500mA，堵转电流各 1.2~1.8A，任何板载 5V（USB / ST-Link 的 100~200mA）都不可能承受。正确架构是”各吃各的电，只共地”：

```text
①18650×2 (7.4V) → MP1584 → 5V ──→ 舵机 VCC
                                   │
                            GND 与 STM32 GND 相连（共地）
②ST-Link 供电→STM32
③PA6/PA7/PB0 只输出 PWM 信号
```

**为什么必须共地**

电压必须有参考。电路中，GND 就是所有电压的参考零点。共地 = 用一根线把两边 GND 连起来，信号才有统一参考点，舵机才能听懂信号。

**舵机的信号电压和供电电压**

①5v是舵机的供电电压，3.3v则是舵机在此接受的信号电压。

②舵机接受的信号电压阈值是2.0v,当大于阈值时即可读取信号，在此装置里，因为STM32F103是3.3v的供电，所以舵机信号电压为3.3v

**问题与解决**

| 问题 | 根因 | 解法 |
| --- | --- | --- |
| 供电问题，舵机时好时坏 | ST-Link 5V （100~200mA）带不动舵机（300~500mA），电压拉垮导致芯片复位 | 改为独立供电 |
| 输出调到 2 点几伏上不去 | MP1584并未和电源的红黑线焊在一起，接触不良 | 采用杜邦线以及蛮力强行固定 |

## 七、前臂负载问题与橡皮筋配力

**功能描述：** 前臂 + 夹爪两个舵机的重量压在肘关节上，导致：

1. 向上抬：实际到位角度 < 指令角度（舵机要克服重力，响应滞后）
2. 向下放：动作过猛、冲过头（重力帮着加速，负载变成”自由落体”）
3. 静止时，机械臂前端会自己下落

**开发历程（10.11-10.12）：**

**解决办法**

1. 机械配力：橡皮筋抬起方向辅助拉平衡
2. 代码缓降：下放不走一步到位，改小步分段缓降

**补偿函数**

```c
/* 肘部带补偿的上升：指令 = 目标 + 补偿值，实际到位正好是目标 */
void Elbow_Raise_Bias(uint8_t target, uint8_t raise_bias, uint8_t *cur_angle)
{
    uint8_t cmd = target + raise_bias;
    if (cmd > 180) cmd = 180;
    Servo_Set(TIM_CHANNEL_2, cmd);
    HAL_Delay(400);
    *cur_angle = target;
}
```

**橡皮筋配力方案实施**

**方案选择**

考虑到”不大改结构”，选择橡皮筋辅助

**挂法**

1. 取细橡皮筋 1根，对折

2. 一端在肘部舵机

3. 另一端在肩部舵机

4. 斜跨关节侧面，不压在转轴正中央，不影响转动

5. 绷紧要适度：太松无效果，太紧会把臂往回拽

**效果与后续**

在使用皮筋后，发现效果仍然不理想，太松无法起到配重效果，太紧则阻碍了肘部的运动

所以机械臂头重脚轻问题并未解决，已告知机械组同学

## 九、代码调试排错记录

**功能描述：** 记录 10.11-10.12 阶段的三处编译报错，以及每处的定位与修复。

**开发历程（10.11-10.12）：**

**问题1：undefined identifier 'elbow_now'**

- 现象：while 里用到 elbow_now，编译报”未声明的标识符”。
- 原因：变量声明遗漏了，且必须写在 while(1) 之前（C 语言先声明后使用）。
- 修复：在 while (1) 上方补 uint16_t elbow_now = 1500

**问题2：implicit conversion from 'int' to 'uint8_t' changes value from 1500 to 220**

- 现象：编译通过但有 5 个警告，changes value from 1500 to 220、comparison ... always false。
- 原因：uint8_t 是 8 位无符号数，上限仅 255。1500 被截断为 220（1500 − 5×256 = 220），导致 while (elbow_now > 1300) 永远不成立，两个缓降循环一次都不执行。
- 修复：变量类型改为 uint16_t（上限 65535，装脉宽绰绰有余）。
- 收获：看到 changes value from X to Y（数字明显变小）的警告，就可以联想到类型装不下，换更大的类型。用脉宽就必须 uint16_t；只有用角度（0~180）才可以用 uint8_t。

**问题3：use of undeclared identifier 'Servo_SetUs'（did you mean 'Servo_Set'?）**

- 现象：while 中调用 Servo_SetUs，编译报未声明。
- 原因：忘记在 USER CODE BEGIN 0 区域定义函数本体。
- 修复：在 Servo_Set 函数之后补上 Servo_SetUs 的定义（必须放在 main() 之前）。

## 十、一键抓取参数标定与流程打通

**功能描述：** 把整个抓取流程拆成固定的几步，每一步让机械臂走到定好的位置，全部写在在代码里。按一下，它就自己从头做到尾。

整个流程：

```text
① 回中位 + 张开爪子
② 肩关节前伸，对准方块
③ 肘关节下探，到方块高度
④ 夹紧
⑤ 肘关节抬起，把方块提起来
⑥ 肩关节后摆，转到后面收集区
⑦松开爪子，方块掉落
⑧退回准备位置
```

**开发历程（10.13）：**

一键抓取流程打通

**调试过程**

采取的是”一步一步卡住看”的办法：

1. 把主循环改成只跑一步，然后用 while(1);卡死
2. 烧录，看动作对不对
3. 不对就改数字 → 重新烧录 → 再看
4. 对上了，再放开下一步，继续调

一次只调一个参数，这样出错能马上找到是哪个参数的问题。

**最终标定出来的参数**

| 参数 | 作用 | 值 |
| --- | --- | --- |
| S_FWD | 肩前伸 | 1300 |
| S_BACK | 肩后摆 | 700 |
| E_DOWN | 肘下探 | 1000 |
| E_LIFT | 肘抬起 | 2500 |
| E_DROP | 肘放下 | 1350 |
| G_OPEN | 爪张开 | 2000 |
| G_CLOSE | 爪夹紧 | 1700 |

**脉宽到达极限，角度却没到位**

**遇见的问题**

调肘关节下探的时候，怎么调都够不到方块。起初以为是脉宽数字不够小，就一路往下改：

1200 → 1100 → 1000 → 900 → 800 → 700 → 600 → 500

角度参数已经调到 500 （舵机能识别的最小值），可是肘关节还是没有降到想要的位置。

但是用手去转这个关节，它其实还能继续往下转。

**困惑**

> 数字已经到 500 了，程序说’到底了’，但机械上明明还能再往下，为什么？

**原因：初始位没对**

问题的根源不在代码，在安装。

舵机能识别的脉宽就是 500 ~ 2500 这一段（对应它输出轴转 180°）。这是舵机的”电行程”，它不认识比 500 更小的数字。

但是摇臂装在舵机轴上的时候，齿位没对好。结果就是：脉宽对应的角度和机械实际角度不对应。

即不是舵机没力气，是”我想要的位置”落在了舵机能指挥的范围之外。

**解决方案：卸掉肘部，重新装**

1. 先把肘部通电，让它走到 1500（中位）
2. 断掉舵机电源
3. 拧下摇臂中心的螺丝，把臂卸下来
4. 手动转动舵机输出轴，转到大约中间的位置
5. 把臂摆成我想要的中位姿态
6. 对准齿位，把臂重新装回去
7. 拧紧螺丝

装完之后：同样的 500~2500 这段电行程，覆盖的机械范围完全变了——下探空间一下就腾出来了，肘关节能降到需要的位置了。

**装好之后：**

所有参数都要重新测。因为齿位变了，每个脉宽对应的机械位置全都不一样了。

**机械臂自己跑完整个流程**

所有参数标定完之后，把主循环修改：

```c
while (1)
{
    Grab_Cube();        // 一键抓取，跑完九步
    HAL_Delay(3000);    // 停 3 秒，再来一遍
}
```

上电之后，机械臂从头到尾自己做完了：

回中位 → 张爪 → 前伸 → 下探 → 夹紧 → 抬起 → 后摆  → 松爪 → 退回

**中间出现问题**

舵机发烫：肩关节带负载动作时烫手。原因是它扛着整条臂 + 多个舵机的重量，力臂又长。

解决办法：

动作速度放慢（用 Servo_Smooth）

**PWM 的数据**

| 参数 | 是什么 | 能不能改 |
| --- | --- | --- |
| PSC = 71 | 预分频，决定”每 20ms 发一个脉冲”（50Hz） | ❌ 不能改，舵机就认这个节奏 |
| ARR = 19999 | 同上，两个一起算出 20ms | ❌ 不能改 |
| SET_COMPARE（脉宽） | 决定舵机转到哪 | ✅ 随便改，这就是位置指令 |

## 十一、PS2 手柄遥控

**功能描述：** 机械臂方向：连接手柄，和底座联调

**两个关键原理**

1. 串行通信就是”用时间换引脚”：一根线一次传 1 位，8 拍传完 1 字节。
2. 按键是低电平有效：数据里某位 = 0 才是”按下”。代码里判断要写 (keys & 按键位) == 0，写反了程序就”永远在动”。

**开发历程（10.16-10.18）：**

**接线记录**

**引脚分配**

| 接收器丝印 | 接 STM32 | 备注 |
| --- | --- | --- |
| GND | 蓝条（GND） | 共地 |
| VCC | 红条（3.3V） | 不接 5V，怕烧 |
| DAT | PB14 | 输入，配置上拉 |
| CMD | PB13 | 输出 |
| CS | PB12 | 输出 |
| CLK | PB15 | 输出 |

**问题一：供电**

一开始我觉得“板子上只有一个 3.3V 脚没办法共用”。后来知道了，利用面包板的电源轨：一个引脚插进红条，红条上任何位置都能取电，并联而已，跟三个舵机共用 MP1584 是一个道理。

**今晚的主线悲剧：手柄配对不上**

**现象**

- 接收器绿灯常亮（有电），红灯一直快速频闪
- 手柄红灯常亮，绿灯按 MODE 键会亮/灭切换
- MODE、START 各种按，手柄重上电、接收器重上电，全试了——连不上

**排查过程（重要的部分）**

| 尝试 | 结果 | 说明问题 |
| --- | --- | --- |
| 按手柄 MODE 键 | 绿灯亮/灭切换 | 手柄本体正常、按键有效 |
| 先开接收器后开手柄 | 没用 | 不是上电顺序问题 |
| 手柄彻底断电重上 | 没用 | 手柄”记忆”不是原因 |
| 观察灯的组合 | 接收器频闪、手柄灯常亮 | 说明手柄可能和其他东西配对上了 |

尝试了较长时间，但是仍未配对上，选择先跳过进行下一步，即对stm32进行独立供电。

遥控器连接准备等到第二天和电控组另外一名成员进行联调。

**手柄终于连接上**

今天和队友一起排查，两个人分头交叉验证：手柄没问题、接收器没问题、代码没问题——问题出在最不起眼的地方：其中一块STM32 主控板太老了，引脚接触不良，时好时坏。

**学到什么**

硬件排查的正确顺序：先怀疑连接，再怀疑设备，最后怀疑代码。

## 十三、阶段总结与反思

**10.9-10.10 阶段（供电与链接）**

①调试思维：链接错误=文件缺位、编译错误=结构笔误、时好时坏=供电等。分层定位（编译→链接→烧录→运行→供电→信号）比盲目重试有效。

②CubeMX 代码保护机制：自写代码必须放在 /* USER CODE BEGIN/END */ 之间，否则重新生成时被覆盖；

③工程文件归属（tim.c 链接）要检查。

④供电设计先行：电流预算应在写代码之前规划，否则会付出双倍调试时间。

**10.11-10.12 阶段（技术层面）**

①调试思维：链接错误=文件缺位、编译错误=结构笔误、时好时坏=供电等。分层定位（编译→链接→烧录→运行→供电→信号）比盲目重试有效。

②机械先于代码：前臂过重这类问题，先想橡皮筋 / 配重，代码补偿只是兜底。先用物理办法解决物理问题。

③数值类型的学习：脉宽必须 uint16_t。uint8_t 截断会编译通过但行为全错。

**10.11-10.12 阶段（工程习惯）**

①只在 USER CODE BEGIN/END 之间写代码，骨架结构（while(1)、注释标记、括号）永远保留。

②看懂报错再改

③文档即调试记录：本日志中记录的每一个问题，都是下次同类问题的现成答案，可以不断迁移运用和改进。

**10.13 阶段**

**1. 机械能动≠ 程序能指挥到**

舵机只认识 500~2500，如果安装位置没对准，机械上能到的位置，程序可能根本够不着。先看看机械，再改代码。

**2. 用物理办法解决物理问题**

皮筋配重、重新装摇臂——这些”动手”的办法比在代码里修改有效得多。

**3. 一次只调一个参数**

调试的时候改一个数、跑一次、看一次，出现问题能马上定位。
